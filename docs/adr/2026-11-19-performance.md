# ADR: производительность запуска, сцены и длинных сессий

**Контекст:** production baseline на 4 Мбит/с и 100 мс: холодный мобильный welcome 1540–1609 мс,
interactive 2049–2142 мс при цели менее 2 секунд. Тёплый запуск занимает 594–678 мс, офлайн —
80–155 мс; полный кэш готов за 10,4–14,5 секунды. Отключение service worker оставляет interactive
на уровне 2011–2062 мс, поэтому он не является основным узким местом. Первичный CSS содержит все
235 SVG-флагов (84,5 КБ сжатого ответа), TTF-шрифт занимает 118 КБ. Runtime baseline: p95 отклика
обычных действий 17,9 мс, тяжёлых 17,3 мс, но сцена 57,2 fps. За 10 жизней retained DOM вырос на
13 819 узлов, listeners — на 1424. `DOM.getDetachedDomNodes` показал полные старые `memorial-view ended`:
`memoryCache` хранит canvas, который после вставки в DOM удерживает через `parentNode` весь экран.

**Решение:**
- Хранить в `Scene.memoryCache` только offscreen-canvas, никогда не вставленный в DOM. `memoryScene`
  возвращает независимую копию с теми же пикселями. `peopleCache` ограничен 128, `memoryCache` — 64
  производными canvas с LRU; загруженные изображения остаются общими. После `load/error` обработчики
  изображений очищаются, чтобы кэш ресурсов не удерживал замыкания и лишние listeners.
- Не перерисовывать сцену, если кадр анимации, параллакс, состояние и набор загруженных ресурсов не
  изменились. Главный `requestAnimationFrame` продолжает управлять временем игры; пропуск касается
  только повторной отрисовки одинакового canvas.
- `scene.prepare` получает монотонную версию: завершение устаревшей загрузки не вызывает render.
  `renderWelcome` отменяет актуальность предыдущего prepare, поэтому старый мемориал не заменяет новый
  стартовый экран. Общие `pending` изображения по-прежнему дедуплицируются в `Scene`.
- Подавать Press Start 2P как WOFF2 с теми же glyph outlines и локальным OFL. Вместо встраивания всех
  флагов в первичный CSS загружать SVG текущей страны. Все 235 используемых ISO2 SVG копируются в
  production и полный оффлайн-кэш, визуальный источник `flag-icons` не меняется.
- Добавить воспроизводимые `perf-startup` и `perf-runtime` прогоны с порогами из грилла. Сейвы,
  механика, баланс, статистические данные и утверждённые пиксели людей/окружения не меняются.

**Альтернативы:**
- A) Отложить регистрацию service worker — небольшой эффект подтверждён экспериментом, но основная
  задержка остаётся; как самостоятельное решение отклонено.
- B) Удалять кэш сцен при каждой новой жизни — устраняет рост, но вызывает повторную работу внутри
  поколения и не исправляет удержание DOM через вставленный cached canvas.
- C) Оставить TTF и общий CSS флагов — проще, но сохраняет лишние первичные байты и задержку сети.
- D) Сократить статистические таблицы или обрезать будущие годы — не требуется для текущей цели и
  создаёт риск изменения статистического контракта.

**Последствия:** повторный рендер мемориала копирует небольшой canvas 128×72, зато старые DOM-деревья
могут собираться GC. При превышении LRU пересобираются только производные canvas, не исходные PNG.
Флаги становятся отдельными запросами при открытии политики; офлайн они доступны после полной установки.
WOFF2 должен поддерживаться целевыми современными PWA-браузерами. Размер `public/` остаётся ≤51 МиБ.
Перед замером retained memory бенчмарк ждёт завершения отрисовок и дважды вызывает GC. Рост узлов от
лениво наполняемых ограниченных image/canvas-кэшей не считается утечкой экрана: отдельный DOM-снимок
обязан показывать ноль retained `memorial-view`/`game-shell`, а listeners и timers не должны расти.
Допуск измерителя кадров — 0,1 мс на дискретность timestamps Chrome и 0,5 fps на VSYNC-джиттер;
целевые 16,7/33,3 мс и 60/30 fps в отчётах не меняются.

## Реализация и приёмка

1. Исправить владение DOM и LRU, повторить 10 циклов и три поколения с DOM/listeners/heap замерами.
2. Пропускать неизменённые кадры, сравнить 81 уникальный кадр и все production-снимки.
3. Собрать WOFF2 и отдельные локальные флаги, проверить glyph outlines, флаг online/offline и размер пакета.
4. Повторить полную startup-матрицу, desktop/mobile runtime, 151+ тестов, сборку и exhaustive-аудит арта.
5. Обновить документы фактическими результатами. Коммит и публикация только по явной просьбе пользователя.

## Фактическая приёмка

- `shots/perf-startup-final`: все 15 замеров passed; мобильный cold welcome 1349–1423 мс,
  interactive 1711–1760 мс, полный кэш 7,4–7,8 секунды.
- `shots/perf-runtime-desktop-final-3` и `shots/perf-runtime-mobile-final-3`: passed, около 60 fps,
  p95 UI 15,2/16,1 и 18,6/22,8 мс, heap +3,63%/+7,28%, retained screens 0.
- 152 теста, production build, `test:scene`, `test:politics-flag`, 1000 жизней и 1000 семей по 3
  поколения прошли. `public/` занимает 49,39 МиБ; WOFF2 29 728 байт вместо 118 204 с идентичными
  начертаниями; 235 флагов доступны online/offline.
- `shots/perf-ui-final`: 62 экрана, ошибки/переполнения/pixel ratio пустые, 32 момента, политика,
  3 поколения и оффлайн пройдены. `shots/perf-visual-matrix`: 81 уникальный кадр, passed.
- `shots/perf-full-production`: 28 512 сочетаний / 228 096 кадров, aggregate и modules passed.
  Static audit 208 PNG / 4 352 450 байт: badAlpha/empty/edge/hole пустые.
- Живой тест пользователя и публикация остаются следующими действиями; коммит не создавался.
